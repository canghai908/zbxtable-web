# 面向普通运维的值班排班

目标：普通账号可只读查班，管理员可维护；今日当班与本人的当前/后续班次可直接找到；明确首次日期、交接时刻和全天覆盖，保存前可检查成员通知渠道配置。保留现有分发、快照、临时代班、兜底与自然日轮班语义。

实现边界：
- 后端单一RegisterOnCallRoutes同时用于正式路由与权限测试。名单、详情、预览和overview只读面向启用的admin/user；写入及audit仅admin，匿名/禁用账号拒绝。
- directory仅提供身份、姓名、账号状态和三个渠道配置布尔值；不得下发邮箱地址、密码或机器人密钥。
- overview按服务器当前时间、每份排班自己的时区生成今日班次；我的值班身份以登录账号派生，过滤在分页前，摘要只计算当前页。下一班包含当前或未来31天首次本人时段，明确查询范围，不表示永久没有值班。
- 编辑器首次日期和交接钟点独立，组合为兼容原schema的start。未编辑旧起点时保留RFC3339原值及精度。编辑后的DST不存在/重复钟点不静默校正；全天开关映射原有相等覆盖时间。
- 页面保持七列紧凑日历、受限高度完整详情、服务端分页与请求防串页。普通账号隐藏并防止手动触发写方法。
- 渠道检查仅代表用户启用和地址配置，不代表实际投递成功；缺少某渠道不阻止其他渠道和兜底继续使用。

验证：既有前端回归加编辑时区/起点精度、权限视图/防串页和渠道检查测试；真实PostgreSQL权限、敏感字段、跨时区今日/本人班次及分页测试；Go全量/竞态/vet/build/gofmt与前端lint/build；桌面/手机管理员及普通账号隔离视觉验证。
